# Amendment note: block-exact counterbalancing

Date: 2026-11-07 (revised 2026-11-08). Status: documented before the first participant was run (no data had been collected).

## Deviation from the pre-registered counterbalancing statement

The preregistration states that on/off-pattern labels of memory items and stars are balanced per encoding ordinal across each 24-trial condition pool. Before data collection we additionally require exact balance, within each 60-trial block (12 trials of each of the five trial types) and for every trial type (I_only carries stars only, D_only and T_only memory items only, I+D and I+T both), of:

- M/S slot occupancy: 6 trials per slot (each half is built from 6 of the 7 complement pairs of the 14 valid strings, 12 distinct strings; the two blocks leave out different pairs, so the pool still uses all 14 strings, none more than twice);
- on/off labels of memory items: 3 on and 3 off among the 6 trials that have a memory item at each serial position (1 to 6 among all stimuli); 6 on and 6 off per memory ordinal; exactly 3 on-pattern items per rotation stratum (not T_only, which has no rotation); 9 on and 9 off per background shade;
- stars: 3 on and 3 off per serial position; 6 and 6 per star ordinal; 3 and 3 per rotation stratum; 9 and 9 per shade;
- probe type x test position (3 per cell), encoding position x test position (4 per cell), target class x encoding position x test position (1 per cell), 3 probed targets per serial position (1 or 2 of them on-pattern), 0 to 3 target probes per trial with the number of trials per target count pinned to (2,4,4,2) / (1,5,5,1) per half and (3,9,9,3) per pool (revision 2026-11-13, see the section below);
- probe type x shade (4 or 5 per cell) and probe type x test position x shade (1 or 2 per cell; the second block complements the first);
- rotation strata (2 angles per stratum; 6 negative and 6 non-negative) and shade (6 white, 6 gray);
- the per-trial number of on-pattern items (memory items and stars separately) as the histogram (2,4,4,2) in one block and (1,5,5,1) in the other, i.e. 3, 9, 9 and 3 trials with 0, 1, 2 and 3 on-pattern items per 24-trial pool (it is not forced into 1 to 2, which would be a deterministic cue).

Per 24-trial pool: probed target-probe on/off labels are exactly 3 on and 3 off at every serial position (within one per block: each block has 3 probed targets at each position, an odd number, so a block holds 1 or 2 on-pattern targets at a position and the other block holds the complement); probe type x shade is 9 per cell and probe type x test position x shade 3 per cell; memory label x rotation stratum is exactly 6 on-pattern items per stratum; the 14 strings are each used at most twice; each rotation stratum has 4 distinct angles (2 per block).

Cells are NOT balanced exactly. The grid cell of every encoded dot or tone, star, dummy and foil probe is drawn independently and uniformly given its on/off label and the exclusions of its trial (no repeated cell within a trial, foils not on encoded, star or dummy cells, tone spacing of at least 3 ranks). Tones use fixed weighted distributions that give every pitch the same expected use. This was a deliberate decision, see "Why cells are not balanced".

The rationale is to make label x serial-position structure identical across all five trial types and both blocks so that single-vs-dual and Block A-vs-B comparisons cannot be confounded with label or position. The change affects only the assignment of already-planned stimulus properties; no hypothesis, test or exclusion rule is altered; no data had been collected.

## Why cells are not balanced

A first version used every grid cell exactly 3 times per pool (as an encoded item, and as a star) and chose foil cells greedily (least used first). A reviewer pointed out that this creates a cue: a participant who remembers which cells were shown or probed earlier can infer target vs foil from the cell history. We measured it with a held-out lookup classifier whose only feature is the participant-visible history of the probed cell (times encoded earlier in the same condition, times probed earlier, block), trained on the probes of 400 plans and scored on the probes of 400 other plans (800 plans in total; `node scripts/cue-analysis.js 800`):

- exact cell usage and greedy foils: 0.694 accuracy. This figure belongs to the first, uncommitted version of this work, not to the previous committed generator;
- previous committed generator: 0.501 accuracy;
- independent uniform cell draws (shipped): 0.505 accuracy (chance 0.500; `node scripts/cue-analysis.js 800` gives 0.5051).

The cell-history cue is closed. This is the only cue this note claims to have closed (see "Known limits" for counting cues that remain).

`tests/cell-history-cue.test.js` repeats the measurement on 150 plans and requires |accuracy - 0.5| < 0.03 (two-sided; the tolerance is derived from the sampling error in the test comment), as a guard against reintroducing exact cell usage.

## What changed in the program

- Each condition's 24-trial pool is generated as two exact 12-trial halves (Main A, Main B), not as a 24-pool partitioned afterwards (`src/scheduler/balanced-pool.js`). Per pool the rotation angles (D_only display angles included) are drawn first, then the omitted pairs, then each half is searched. `within-trial.js` and the other legacy single-pool generators are now used only for the practice blocks; those generators are unchanged and bit-identical for equal PRNG state.
- `src/scheduler/balance-invariants.js` recomputes every count above from the planned trials, including: no foil on a dummy cell, the stored probe `pattern_label` agreeing with the probed cell and the probe type, and at plan level `presentation_index`, `block_position` and `trial_uid` agreeing with the position. `generateMainPlan` checks every pool and, at the end, the whole plan as it will be shipped (after the trial-order planner, which only reorders whole trials of one type inside a block); a plan that is not exact is never returned (it throws, and the runner shows its start-up failure screen).
- A global, deterministic attempt budget (an attempt count, not time) bounds the work of one `generateMainPlan` call, so a degenerate random stream fails within about two seconds instead of stalling the page; real seeds use a small fraction of it (`tests/main-plan-budget.test.js`).
- All earlier pre-registered balances still hold (they are the per-pool sums of the block-level balances): probe type x position 6 per cell, encoding position x position 8 per cell, 12 on and 12 off memory labels per encoding position, 12 on and 12 off star labels per star position, 12 white and 12 gray per pool, 4 angles per rotation stratum with 12 negative.
- `pre-reg/pre-reg.json` counterbalance_invariants: three claims were added (`block_exact_slot_label_balance`, `block_exact_probe_and_design_balance`, `pool_exact_target_labels_and_cell_usage`) and two existing statements were corrected to what the program now does (`within_trial_run_length`: the 24 sequences are no longer "drawn with replacement" but are 12 distinct strings per half; `rotation_angles_and_order`: D_only angles are drawn first at pool level, not last). No balance was weakened.

## Known limits

- Foil cells (and encoded and star cells) are not balanced: cells are drawn independently and uniformly given label and exclusions, so per-cell usage varies from pool to pool and is equal only in expectation. Tone pitches likewise have equal expected, not exact, use.
- Probed targets per serial slot x on/off label are exact only per pool (within one per block).
- Pattern-reminder exposure (imagery trials only) and the parity of tone pitch with the on/off label are structural features of the design, unchanged and outside this amendment.
- The within-trial structure of 1 to 2 target probes per trial is inherited from the earlier design: after two targets the third probe is a foil, after two foils it is a target (TT -> foil, FF -> target).
- The per-trial composition (how many on-pattern items a trial has) is constrained only through the histogram above.
- Serial slot x test position and probe type x rotation stratum are not balanced.
- The mapping from seed to plan changed: the runner already built the main plan before practice in the previous build (src/runner.js:187), but the main plan now consumes a different number of PRNG draws in a different order, so the practice trials for a given seed differ from those of the previous build. The practice generators are unchanged and produce identical output for an identical PRNG state; the schedule of a session is still reproducible from its seed string.

## Remaining-count (counting) predictability and the pre-registered sensitivity analysis

The exact within-block balances create counting cues. This note does NOT claim that the new generator is no more predictable than the previous one: it is more predictable in the following respects. Figures come from an independent second review with held-out classifiers on 1400 plans per generator tree (new generator versus the previous committed generator).

1. Target vs foil from the participant's own earlier responses. A classifier that tracks target/foil counters per (label, position) within the block reaches accuracy 0.685 (previous: 0.559); with shade, 0.647 (0.534). Block B predicted from Block A's counts alone: 0.6145 (95% CI 0.6126 to 0.6163) versus 0.564. Block B with pool-remaining counts from A and B so far: 0.759 versus 0.579. By task-trial index k = 0..11 within a block the counter accuracy is 0.50, 0.55, 0.57, 0.59, 0.62, 0.64, 0.66, 0.70, 0.735, 0.785, 0.859, 1.000 (the previous generator tops out at 0.607). Hence the target status of all 3 probes of the 12th trial of each task in each block is exactly determined, the number of targets (1 vs 2) is exactly known at k = 11 (every block has exactly 6 two-target trials per task), and because Block B complements Block A about 43% of Block B probes are forced.
2. Exploitability. Using this needs 12 to 24 running counters and a record of the true target status of 60 interleaved trials. We judge this infeasible for ordinary participants; a scripted or very strategic participant would gain mainly on the last 2 to 3 trials per task per block (about 8% of trials).
3. Within-block remaining-count predictability of item labels. Each slot holds exactly 3 on and 3 off items per block, so the 6th occupant of a slot is forced (about 26% of items are forced at a cap). Memory label from slot history: accuracy 0.685 (previous 0.516); star label 0.685 (0.562); with all counters 0.76 (previous 0.54) for memory labels and 0.59 for star labels (as reported by the reviewer; no previous-generator figure is quoted here). This is intrinsic to the required slot balance and is not a cell cue. Memory labels are visible at probe time, so they do not predict a response.
4. Stratum partners have complementary on-counts. In 9600 of 9600 stratum-blocks the two trials of a rotation stratum sum to exactly 3 on-pattern items (memory items and stars); in the previous generator the sum varied. Human exploitability is doubtful.
5. Inherited, unchanged by this work: tone spacing within a trial (two probe tones less than 3 ranks apart are always both foils; P(target) = 0.000 at rank distance 1 or 2 and 0.52 to 0.57 at distance 3 to 5), giving classifier accuracy 0.547 for t_only and 0.548 for i_t (previous: 0.548 and 0.552); and the within-trial rule that after two targets (TT) the third probe is a foil and after two foils (FF) it is a target (p = 1.0 at the same rate as before).

Pre-registered sensitivity analysis (committed before data collection). Every confirmatory analysis that uses probe responses will be reported twice: (a) on all trials and (b) excluding the last k = 3 trials of each task in each block (task-trial index 9, 10, 11 within a block, where counting accuracy is 0.785 to 1.000), or equivalently with a covariate for those trials. Conclusions are called robust only if (a) and (b) agree in direction and inferential decision.

## Revision 2026-11-13: 0 to 3 targets per trial, number of trials per target count pinned to (3, 9, 9, 3)

Recorded for transparency. It was made after the first three pilot sessions and before any confirmatory data collection; no hypothesis, test, threshold or exclusion rule changed.

**Why.** Every memory trial had exactly 3 probes with exactly 1 or 2 targets (exactly 6 + 6 trials per 12-trial half). A participant who learns each probe's true type from the feedback could therefore infer the third probe in one third of the trials: after two targets (TT) the third was always a foil, after two foils (FF) always a target (point 5 of the predictability note above: "p = 1.0 at the same rate as before"). In the three pilot sessions the third-probe accuracy was higher in those forced trials (.79) than in the others (.68). The original Experiment 2 had the same structure (all 3,840 of its trials had 1 or 2 targets), so this is a deviation from Experiment 2 and is filed as such.

**What changed.** A memory trial (D_only, T_only, I_D, I_T) may now have 0, 1, 2 or 3 target probes (so also 3 foils or no foil). The number of trials per target count is pinned, exactly as the number of on-pattern items per trial already was: (2,4,4,2) trials with 0, 1, 2, 3 targets in one 12-trial half and (1,5,5,1) in the other, which gives (3,9,9,3) per 24-trial pool, the 1 : 3 : 3 : 1 split of a fair coin per probe. Which half gets which histogram is drawn from the seed. Every half still has exactly 18 targets (6 per test position). Practice trials follow the same rule (without pinning, two trials per task).

**Unchanged.** Every other exact balance of the block-exact generator (probe type x test position, encoding position x test position, target class x encoding position x test position, 3 probed targets per serial position with 1 or 2 T_on, label, shade and rotation-stratum balances, the 14 sequence strings); no probe type appears 3 times in a trial; a foil is never on an encoded, star or placeholder cell and foils of a trial are distinct; tone foils are at least 3 ranks from the encoded tones; cells stay independent draws.

**Measured (400 simulated sessions, 38,400 memory trials, cap kept).** P(third probe is a target | first two TT) = 0.502, | FF = 0.498, | TF = 0.506, | FT = 0.494; P(second = target | first = T) = 0.498, | F = 0.502; each of the eight patterns TTT..FFF occurs in 12.4 to 12.7 % of trials (1/8 each in expectation). The held-out cell-history classifier is unchanged (0.5086 against 0.5000 over 115,200 probes). Generation succeeded for every seed (worst case 22 attempts per pool against a budget of 1600).

**Remaining predictability, stated plainly.** The exact histogram per block creates a counting cue across trials: a participant who counted the trials of each target count in a block would know, near the end of the block, which counts are still missing (for example the number of targets of the last trial of a task in a block is determined). This is the same kind of cue as in the note above and is judged infeasible for ordinary participants; the registered sensitivity analysis (all trials, and excluding the last k = 3 trials of each task per block) remains the safeguard. On the specific points of items 1 and 5 above: the within-trial TT/FF rule no longer exists, and the number of targets of the last trial of a block is no longer "1 vs 2" but one of 0 to 3 given the remaining counts.

Transparent changes to the counterbalancing of the main task, made before any data were collected.

The preregistered counterbalancing balanced the on/off-pattern labels of memory items and stars per encoding position within each 24-trial condition pool. Before data collection we strengthened the stimulus-assignment procedure so that, within each 12-trial half of each condition (Main A and Main B), the following are balanced exactly: memory-slot occupancy across the six serial positions; on/off labels per serial position, per encoding position, per rotation stratum and per background shade; probe type by test position, encoding position by test position, probe type by background shade; probed-target counts per serial position; rotation strata (two angles each) and background shade (six white, six gray). Per 24-trial pool, the probed on-pattern and off-pattern targets are exactly balanced at every serial position. All previously preregistered balances still hold. Grid cells (including foil cells) are deliberately NOT balanced exactly: they are drawn independently and uniformly given their label and trial exclusions, because exact cell usage let earlier cell history predict target versus foil status (held-out classifier accuracy 0.694 with exact usage versus 0.505, chance 0.500, with independent draws). Limits: the exact within-block balances create counting cues that a participant who perfectly tracked the true target status of their own earlier probes could use (target/foil prediction from counters 0.685 versus 0.559 in the previous generator; exactly determined for the 3 probes of the 12th trial of each task per block, with Block B complementing Block A), and item on/off labels and stratum-partner on-counts are likewise forced by remaining counts; we judge this infeasible for ordinary participants and do not claim the plans are as unpredictable as before. The cell-history cue is closed (0.505 versus 0.694 in a first uncommitted version; the previous committed generator gave 0.501). Pre-registered sensitivity analysis: all probe-response analyses will be reported on all trials and again excluding the last 3 trials of each task in each block (or with a covariate for them). Known unbalanced or inherited features: foil-cell usage, serial slot by test position, probe type by rotation stratum, pattern-reminder exposure on imagery trials only, tone pitch parity with the on/off label, and the within-trial structure of one to two target probes per trial. No hypothesis, analysis, exclusion rule or sample size was changed.
